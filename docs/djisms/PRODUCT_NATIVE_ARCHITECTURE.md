# DJISMS native V1 implementation

The user-authorized continuous work package supersedes the older ME1-only deletion scope and per-record confirmation API suggestions. Runtime auto-purge remains limited to the exact frozen preserve/verify/fresh reread/storage-index-PDU match/single CMGD/confirmation/reconciliation contract. The original engineering gates and evidence are unchanged.

- UI: Swift, AppKit, NSStatusItem, UNUserNotificationCenter, local history/search/preferences. A child helper is started directly with `Process`; this is not a Terminal wrapper. Private stdin/stdout pipes carry versioned bounded JSON. There is no listener socket, raw AT method, arbitrary path or index parameter. Parent EOF stops the helper after graceful reconciliation; no LaunchAgent is installed.
- Core: audited Go/C fixed command state machines, raw-first archive, SHA-256 immutable journal, SQLite WAL/FULL/fullfsync projection. System SQLite is linked directly. Existing Python archive v1 remains readable; only derived display metadata is extended. Raw files and prior journal entries are never rewritten. Recovery validates raw receipts, chain, source provenance, messages, notifications and purge attempts against the journal.
- Identity: full reviewed USB configuration plus VID/PID/revision and the current registry entry ID. Location is dynamic and never a persistent identity. Native opens pin the retained registry parent, check the descriptor and IF2 pipe map before every write, and use non-seizing IF2 only. Discovery validates active interfaces and AppleUserECM ownership. Multiple modules inhibit operation. No firmware/NV/USB mode/alternate/interface takeover is implemented.
- Lifecycle: a fresh insertion starts status verification and a new receive session. Every receive session snapshots and preserves the current inventory; CMTI grants a single numeric CMGR in that connection. Direct Class 0 has no fabricated modem slot. Completed new stored arrivals close/reconcile the receiver before any cleanup. Each purge creates a new fixed single-use native transport with a freshly matched slot. Unknown results remain blocked across restart. An ordinary receive-only physical removal closes the old handle; reconnect uses a new registry identity. Removal during purge is a safety stop.
- Shutdown: quit cancels receiving and waits for settings and host reconciliation. A single already-started purge is bounded and completes its confirmation instead of being deliberately interrupted by ordinary quit. A crash leaves its intent durable and blocks retries if the result is unresolved.
- Notification: journal-backed outbox, stable notification identifier derived from exact PDU set, sender and up to 160 characters of body preview. Submission is recorded as `submitted`, not proof the user saw a banner. Denial/failure/disabled notifications do not revoke archive validity. Existing history is suppressed. Duplicate PDU observations remain permanent but share a display message. Resolved incomplete projections are hidden, never erased.
- Network: current device-associated BSD interface and IPv4, unchanged default route and SIP, plus TLS-verified interface-bound Apple connectivity request. Network settings are never modified. A route/address change during a safety operation blocks purge even if independently caused by the user.
- Packaging: self-contained arm64 app, system libraries only at runtime, macOS 14 deployment target; actual compatibility must be established by testing. Development ad-hoc signing is separate from the prepared Developer ID/notarization/staple workflow.

Prior art: [Apple NSStatusItem](https://developer.apple.com/documentation/appkit/nsstatusitem), [notification authorization](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications), [notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). Framework signatures were also checked against the installed Apple SDK through compilation. No new third-party runtime dependency was introduced; the existing audited `github.com/warthog618/sms v0.3.0` supplies PDU primitives.

Acceptance distinguishes automated/offline fault injection from actual SMS delivery, visible notification, physical replug, other-user/clean-Mac testing and iPhone 4G regression. Those cannot be inferred from a successful build or replay.

Historical reviewed recovery (for previously recorded legacy stops): safety stops remain journaled and latched. The engineering-only `djisms-recover` command (not bundled or exposed over IPC) can authorize one exact reviewed receive-only IOKit operation-aborted failure. It verifies the archived closed receive-session summary, absence of unresolved deletion/archive work, changed USB registry identity, unowned IF2, supported profile and two matching fresh SIP/HTTPS host checks. The authorization binds to a fingerprint of that stop and cannot authorize a newer failure. No AT/USB write occurs during authorization. Startup begins with automatic cleanup disabled and runs all normal device, settings and inventory checks. The old failed reconciliation is retained as a failure, not relabeled PASS. Unknown deletion and other faults are ineligible.

Development RC lifecycle update (2026-09-21): new idle receive interruptions are
classified by an explicit clean-boundary/closed/durable proof, not an error-text
match. The runtime retains an inventory checkpoint across restart, waits for
network readiness and retries acquisition through full identity/settings/snapshot
verification. Partial frames, command failures, archive errors and all purge
failures remain stopped. Power hints suspend new operations; a safely closed
receive session can defer host verification to wake with recorded evidence.
Published staging duplicates are retained, never deleted; unmatched staging
bytes block device operations. The legacy engineering authorization above is not
needed for the new eligible automatic path and is still excluded from the App.
